# Chess Studio 3

An offline Android 8+ APK containing all recursively discovered `chess/3/sample*.html` programs. Based on `ae6820dc/9062/android-studios` at `4dbdda945c6fd41b7c717059a68780269be799cf`: same native dark Home menu, Back/Home/Programs/Backup toolbar, system-bar insets, per-program HTTPS asset origins, JavaScript/DOM storage, native JavaScript dialogs and document-picker backup/import controls. The host also calls the original `saveGame()` before navigation, backup export, and pause. No source HTML is edited.

Application ID: `io.github.ae6820dc.chesssamples3`. Output: `apk/chess-studio-3-v1.apk`. Existing APKs are never replaced. A later release must use a new filename and retain this app ID, signing key and origin IDs for saved-data compatibility.

`prepare-assets.py` discovers samples dynamically in natural filename order, extracts their original Program IDs and storage keys, and copies every file under `chess/3` byte-for-byte with its relative path. Each sample has a stable isolated origin derived from its relative filename. Original localStorage keys and game state are retained. No Internet permission is requested. The original samples use inline CSS/JS and Unicode chess pieces and have no external dependencies.

Saved state in an existing browser or a different app cannot be accessed automatically by a distinct Android application ID. Those existing stores remain untouched. The Backup toolbar exports/imports per-program localStorage JSON; restoring requires a matching `chess3-sampleN` program field. Existing saves inside this app survive switching and process restarts. Keep the same key and application ID for future updates; uninstalling or clearing app data removes local saves.

Build: Java 21, Android SDK/build-tools 36, Gradle 8.13, Android Gradle Plugin 8.13.0. Run `gradle -p android-chess assembleDebug assembleDebugAndroidTest lintDebug`. GitHub Actions `.github/workflows/chess-samples-3.yml` builds, checks signed APK bytes against sources, tests every sample on an Android 16 emulator with wireless/data disabled, force-stops and reopens the app to verify saved board/turn/flip and storage isolation, then commits the APK, catalog, hashes and test reports to `apk/`. Publishing is gated on all checks passing and refuses to overwrite the output filename.

The committed signing key is a public development key (password `android`), following the prior APK's development signing process. This is a debug APK, suitable for sideloading, not a Play Store production signing identity. Runtime tests exercise menu completeness, initial board, legal e2-e4 via taps, flip, original Program IDs, original storage keys and persistence for every discovered sample. They do not exhaustively validate every chess rule or device model.
